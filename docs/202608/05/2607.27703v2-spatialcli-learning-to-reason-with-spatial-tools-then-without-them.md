## 摘要
视觉-语言模型（VLMs）越来越多地用于具身代理中，以解释视觉输入、推理空间关系，并基于该推理做出任务级决策。然而，一个根本性的能力不匹配仍然存在：通用VLM能够推理整体任务，但常常遗漏决定成败的视觉细节，而专业视觉模型能够捕捉这些细节，却无法将其转化为任务级决策。在这项工作中，我们提出了SpatialCLI，这是一个教导VLM使用空间工具进行推理，并逐步内化它们所提供的专业感知能力的框架。SpatialCLI分三个阶段进行：（1）调用（Call）将专业视觉模型暴露为空间工具，以增强VLM的感知；（2）学习（Learn）使用冷启动SFT和代理RL来改进工具使用；（3）内化（Internalize）将成功的工具使用轨迹转化为语言，以内化专业感知能力。我们进一步介绍了SpatialCLI-Bench，这是一个包含516个示例的基准，用于跨定位、分割、深度和姿态的组合感知。在MindCube上，SpatialCLI将Qwen3-VL-8B-Instruct从使用工具时的29.3%提升至84.6%，超过了使用工具的GPT-5.6 Sol（72.1%），同时在内化后不使用工具时保持了73.8%的准确率。

## Abstract
Vision-language models (VLMs) are increasingly used in embodied agents to interpret visual inputs, reason about spatial relationships, and make task-level decisions based on that reasoning. However, a fundamental capability mismatch remains: general VLMs can reason about the overall task but often miss the visual details that determine success, while specialist vision models can capture those details but cannot translate them into task-level decisions. In this work, we propose SpatialCLI, a framework that teaches VLMs to reason with spatial tools and progressively internalize the specialist perceptual capabilities they provide. SpatialCLI proceeds in three stages: (1) Call exposes specialist vision models as spatial tools to augment the VLM's perception; (2) Learn uses Cold-Start SFT and agentic RL to improve tool use; and (3) Internalize verbalizes successful tool-use trajectories to internalize specialist perceptual capabilities. We further introduce SpatialCLI-Bench, a 516-example benchmark for compositional perception across localization, segmentation, depth, and pose. On MindCube, SpatialCLI raises Qwen3-VL-8B-Instruct from 29.3% to 84.6% with tools, surpassing GPT-5.6 Sol with tools (72.1%), while retaining 73.8% without tools after internalization.

## 二、方法论：SpatialCLI 框架

SpatialCLI 采用 **Call–Learn–Internalize（调用–学习–内化）** 三阶段流程：

### 1. Call：推理时工具增强
将四个空间工具注册到 ReAct 式交互循环中，VLM 作为智能体决定何时调用工具、如何组合证据并输出最终答案：

- **Locate**：由 Locate Anything + Grounding DINO 融合提供，返回目标边界框与中心点。
- **Segment**：由 SAM 3 提供，返回多边形目标边界（每个连通组件最多 16 个顶点，目标掩码 IoU ≥ 0.97）。
- **Depth**：由 Depth Anything 3 提供，返回指定图像点的度量深度（相机轴距离，米）。
- **Pose**：由 Orient Anything V2（物体朝向）+ VGGT（跨视角相机运动）提供。

关键设计：保留每轮推理内容到完整交互历史（避免冗余推理）；暴露剩余工具调用预算；采用 XML 包裹的 JSON 调用协议。

### 2. Learn：智能体微调
- **冷启动 SFT**：使用 Qwen3.5-397B-A17B 作为教师模型生成工具交互轨迹，过滤无效调用格式、工具执行失败、最终答案错误的样本（保留约 40%，约 2000 条轨迹），建立基本工具使用行为。

## 五、主要结论与发现

1. **外部工具增强效果显著**：SpatialCLI Tools 对性能较弱的模型增益更大（GPT-5.6 Sol 平均提升 6.1 分 vs Qwen3-VL-8B 提升 21.0 分），说明专用感知对基础能力有限的模型价值最大。
2. **训练同时提升直答与工具使用**：所有 SpatialCLI 变体在 w/o Tools 和 w/ Tools 上都超过对应的初始模型。SpatialCLI-8B 在 SpatialCLI-Bench 上 w/o Tools 达 72.7%，w/ Tools 达 91.3%。
3. **能力内化与工具使用可以共存**：双视角训练避免了"内化牺牲工具使用"或"保留工具但无法内化"的矛盾。
4. **冷启动 SFT 对 RL 至关重要**：无 SFT 的 RL 工具调用数从 3.36 膨胀至 6.74，而有 SFT 的 RL 稳定在 2.56 左右。
5. **内化随数据与模型容量持续增长**：数据暴露决定给定模型从专家学习的效果，模型容量决定吸收能力；外部工具则压缩了模型规模差异。
6. **结构化返回优于可视化返回**：显式坐标/多边形是性能提升的主要来源，且更易于 VLM 内化。

## 六、优点

- **框架设计新颖且完整**：Call–Learn–Internalize 三阶段实现了"外部借用→策略学习→能力内化"的完整闭环，解决了此前工作只能"用工具"或只能"直接推理"的二选一困境。
- **渐进式轨迹语言化**：逐轮证据整合避免了长上下文处理和跨轮依赖丢失，且通过在整合阶段隐藏正确答案防止答案条件化重构。
- **双视角联合训练**：通过 λ 平衡内化与工具保持，实证表明两者可兼得。
- **结构化工具接口设计**：融合多专家模型（如 Locate 融合两个检测器的交叉确认公式 b_F = round((2b_L + b_D)/3)），并设计了内容寻址缓存（缓存命中率 Depth 99.2%、Segment 49.4%）。
- **新建高质量基准**：SpatialCLI-Bench 使用"专家模型收集证据→LLM 生成问题→独立人工审核"的四阶段流程，且保留私有 Oracle 计划用于审计。
- **诊断指标完善**：CII 指标系统性地衡量四类能力的内化程度，且有人类专家独立验证参考输出。

## 八、个人思考与启示（批判性分析）

### 1. 对“能力内化”概念的再审视
论文的“内化”本质上是一种**贝叶斯意义上的知识蒸馏**：将工具返回的高置信度结构化证据作为软标签，训练模型在无工具条件下模仿专家的输出分布。这一点从实验结果中可以验证：w/o Tools 性能虽有大幅提升，但始终低于 w/ Tools（72.7% vs 91.3%），说明内化并不能完全替代工具。这提示我们：**内化的上限受限于训练数据中工具证据的信息量**，而非模型自身的推理能力。

### 2. 工具调用预算与强化学习的耦合
论文在 RL 阶段暴露“剩余工具调用预算”并设计了异步 Clip-Higher 的 GRPO 变体，这是一个值得注意的工程细节。它实际上把工具调用的“成本意识”编码进了策略梯度中，避免了模型无限调用工具来“刷分”。但论文没有单独消融“预算暴露”对训练效率的影响，这一点若能补充，将更有说服力。

### 3. 渐进式语言化的替代方案
论文采用“逐轮证据整合 → 全局语言化”的两段式方案，其动机是为了防止正确答案泄露。但这里存在一个潜在缺陷：逐轮整合单元 eₜ 本身由提取器 Ψ_ext 生成，而 Ψ_ext 是一个未经过 RL 优化的固定提示模板，它可能引入自身的偏差。一个更强的设计是让整合过程也参与端到端训练（例如使用可微的压缩器或经过 RL 的摘要模型），但论文未讨论这一点。

### 4. 与世界模型/空间记忆的关系
论文的“内化”本质上是在隐空间中构建一种空间记忆。从这个角度看，SpatialCLI 与最近热门的“世界模型”范式（如视频预测模型）存在互补性：世界模型提供动态预测，SpatialCLI 提供静态空间感知。未来若有工作将两者结合，可能比单独使用任何一种方法更接近“物理世界原生基础模型”这一目标。

### 5. 对 VLA（视觉-语言-动作）模型的启示
虽然论文明确将任务范围限制在“感知中心”任务，但双视角训练（内化视角 + 工具使用视角）非常容易推广到 VLA 场景：工具使用视角可以视为“调用感知模块”，内化视角可以视为“端到端动作生成”。很遗憾论文没有在任一真实机器人平台做验证，这限制了结论向具身智能下游任务的直接推广力度。

### 6. 评价指标的一个盲区
CII 和基准分数都关注“答案正确性”，但忽略了**证据一致性**：模型是否在产生正确答案的同时，其推理链中引用的坐标、深度、位姿数据与真实空间关系一致？一个诊断性实验是只给推理链、不给最终答案，让人类或 LLM 评分推理链的空间正确性。论文没有做这一步，因此无法排除模型“答对了但推理链是事后编造”的作弊路径。

## 十、总体评价与推荐阅读建议

**总体评价**：SpatialCLI 是一篇设计完整、实验扎实、问题定义清晰的系统性工作。它将“工具调用”从一种推理时的临时补丁提升为一种可持续学习的内化信号，这对具身智能和感知-语言交叉领域有明确的参考价值。论文的最大亮点在于双视角联合训练与渐进式轨迹语言化两个设计，最大遗憾在于缺乏真实机器人验证与统计显著性报告。

**推荐阅读群体**：

- **具身智能与 VLA 研究者**：重点阅读第三、四节，关注工具增强与内化信号的迁移潜力。
- **多模态 RL（RLVR）研究者**：重点阅读第三节 Learn 部分，参考 GRPO + DAPO 的异步训练细节与奖励设计。
- **视觉工具组合与空间推理研究者**：重点阅读第二节 Call 部分与第四节实验，参考工具接口与基准构建流程。
- **基础模型评测研究者**：可参考 SpatialCLI-Bench 的“专家模型生成证据 → LLM 生成问题 → 人工审核”的流水线设计。

**可复现性备注**：
- 模型权重与工程代码**未开源**，只提供了评测 API 访问地址（可通过 `clinet.ai` 邮箱反馈获得），这一点对复现构成显著障碍。
- 数据集的构建代码与中间产物（如逐轮整合单元）未见公开描述，进一步降低了精细复现的可行性。

## 十一、与 Related Work 的关系和定位

SpatialCLI 不是第一个提出“工具增强 VLM”的框架（此前已有 SpaceTools、AlloSpatial 等），但其独特定位在于：

| 维度 | SpaceTools / AlloSpatial | SpatialCLI |
|------|--------------------------|------------|
| 目标 | 提升推理时工具使用的准确性 | 既提升工具使用，又通过内化实现无工具推理 |
| 训练信号 | 仅工具执行结果 | 工具执行结果 + 渐进式语言化轨迹 |
| 内化 | 无 | 双视角联合训练（CII 衡量） |
| 工具范围 | 定位 / 检测 | 定位、分割、深度、位姿（四类组合） |
| 评测 | 单一基准 | 7 个基准 + 新基准 + 人类验证 |

论文在此意义上构建了一个新的“工具学习 → 能力内化”研究分支，为后续研究提供了统一的问题定义、评估协议与诊断指标。

## 十二、最终结论

SpatialCLI 的核心贡献可以概括为三点：

1. **提出了一种新的学习范式**：将推理时工具交互转化为模型内化的空间感知能力，实现了“调用–学习–内化”的闭环。
2. **提供了工业化级别的工程实现与评测协议**：包括多专家工具融合、内容寻址缓存、渐进式轨迹语言化、双视角 RL 训练，以及可审计的基准构建流程。
3. **揭示了多个可泛化的实证规律**：如“弱模型从工具中获益更大”“无 SFT 的 RL 导致工具滥用”“结构化返回优于可视化返回”等，这些结论对任何研究工具增强 VLM 的工作都具有参考价值。

其局限也同样明显：任务范围狭窄（仅静态感知）、缺乏统计显著性检验、对比基线训练不充分、未开源、无真实机器人验证。综合来看，这篇论文在**研究问题的新颖性、方案设计的系统性、实验覆盖的广度**上均达到较高水准，但在**公平对比、统计严谨性、下游迁移验证**上有所欠缺。作为一篇 arXiv 技术报告，它为“工具使用 → 能力内化”这一方向奠定了基础，但距离成为该领域的标杆性工作，还需要补充真实环境验证与开放源代码。
